# GPX test routes (Adana)

Synthetic but realistic GPS tracks on the real Adana road network. They feed two kinds of tests:

- **Unit tests of the matching engine** (pure Kotlin): match `<name>.gpx` / `<name>.noisy.gpx` against the region package and compare with `<name>.expected.json` (Phase 0 target: accuracy >= 90 %, wrong segments <= 5 %).
- **End-to-end tests on the Android emulator**: replay a track with `tools/gpx/replay.py` and check drive detection and the painted map.

All files are generated by `tools/gpx/generate.py` from `tools/gpx/routes.json`. Do not edit them by hand; change the config and regenerate.

## Files

Each route has three files:

| File | Content |
| --- | --- |
| `<name>.gpx` | Clean track: exact positions on the road centre line, one point every second |
| `<name>.noisy.gpx` | Same drive with realistic GPS noise and short dropouts (see below) |
| `<name>.expected.json` | What a correct implementation must produce, plus the OSM ids of the route |

Its `osm_node_ids` / `osm_way_ids` are railway elements, not roads. ## expected.json

| Field | Meaning |
| --- | --- |
| `scenario`, `mode` | Description; `drive`, `walk` or `train` (how the profile was generated) |
| `expected.result` | `drive` or `not_drive` |
| `expected.drive_count` | Number of drives the detector must produce from this track |
| `expected.notes` | Extra pass criteria, if any |
| `osm_node_ids` | Ordered OSM node ids along the route (exact ids from the OSM extract) |
| `osm_way_ids` | Ordered OSM way ids along the route (consecutive duplicates collapsed) |
| `ways` | Per way: highway class, name, ref, oneway, legal limit used and whether it came from a `maxspeed` tag or the Turkish default |
| `parallel_ways_not_driven` | (`parallel-roads` only) ways running alongside the route that must stay undriven |
| `distance_m`, `duration_s` | Route length along the node polyline; first to last timestamp |
| `points` | Point counts of the clean and noisy files and how many points the noisy file dropped |
| `speed_kmh` | `avg` (distance / duration), `avg_moving` (> 0.5 m/s), `max`, `max_limit_on_route` |
| `stops` | Planned stops: `traffic_light`, `traffic_jam`, `station` (`at_m`, `duration_s`) and `stop_and_go` stretches |
| `waypoints`, `road_names` | Routing input (lat, lon, optional heading) and the main road names OSRM reported |
| `data` | OSM extract file and its replication timestamp (`2026-11-15T21:22:28Z`), routing source, random seed, OSRM distance, unresolved OSRM nodes |

The node and way ids come from the same Geofabrik extract as the region package (`tools/regions`, `turkey-261115.osm.pbf`), so they can be compared directly with the package's segments (OSM way id + sequence). A route's first and last node is the far end of the edge its start/end waypoint sits on.

## Track format

- GPX 1.1, one `<trk>` with one `<trkseg>`; every `<trkpt>` has `lat`/`lon` (7 decimals) and `<time>` (UTC, ISO 8601).
- Speed and course are in the Garmin TrackPointExtension v2 (`xmlns:gpxtpx="http://www.garmin.com/xmlschemas/TrackPointExtension/v2"`): `<gpxtpx:speed>` in **m/s**, `<gpxtpx:course>` in **degrees clockwise from true north**. GPX 1.1 has no standard speed/course element.
- Clean files: consecutive points exactly 1 s apart, first and last point at rest.
- Noisy files: positions carry a slowly varying, time-correlated offset (Gauss-Markov, sigma 6 m per axis, correlation time 30 s) plus 1.5 m white jitter, so the error is mostly 5-10 m and drifts instead of jumping; speed +-0.3 m/s, course +-4 deg noise; while stopped the position still drifts and speed reads ~0. About one dropout per 150 s removes 2-5 consecutive points, so the gap between two remaining points is 1 s or 3-6 s.

## How the tracks are built

1. **Route**: waypoints from `routes.json` go to the public OSRM demo server (`router.project-osrm.org`, car profile) with `annotations=nodes` and `continue_straight=true`. A waypoint may carry a heading; OSRM then snaps it only to a road driven in that direction (+-45 deg), which picks the right carriageway of a divided road. Rail routes use a shortest path over `railway=rail|construction` ways of the OSM extract instead.
2. **Exact OSM ids**: the demo server prints node ids with 10 significant digits, so ids above 1e10 come back rounded. Each id is recovered from the OSM extract: the candidate in the id window that sits at the route geometry point (<= 2 m). Way ids come from the node pairs (each pair must be an edge of an OSM way; `edges_without_way` is 0 for all routes).
3. **Speed profile** (1 m distance grid):
   - legal limit per way: the `maxspeed` tag, else the Turkish default for cars (urban 50; intercity: divided trunk 110, other trunk/primary/secondary 90, motorway 120);
   - cruise speed = limit x 0.86-0.95 on main roads, x 0.60-0.75 on residential streets, hard cap 0.97 x limit; **the profile never exceeds the limit**;
   - curves: `v <= sqrt(2.0 m/s^2 x turn radius)`, so junction turns drop to roughly 15-20 km/h;
   - acceleration <= 1.4 m/s^2, braking <= 2.0 m/s^2 (walk 0.5/0.7, train 0.5/0.7);
   - stops (traffic lights at junctions, traffic jam, station) and stop-and-go stretches from the config.
4. **1 Hz sampling**: the profile is integrated to time and sampled every second; course is the road bearing over +-5 m.
5. **Noise**: see Track format.

Randomness (cruise factors, light durations, noise) uses fixed seeds derived from `defaults.seed` and the route name: the same config and caches give byte-identical files (checked by `test_generation_is_deterministic`).

## Regenerating

```bash
# 1) One-time: extract the Adana road + rail network from the Geofabrik Turkey extract
#    (the same file tools/regions downloads). Needs pyosmium (osmium==4.0.2, see tools/regions/requirements.txt);
#    takes ~15 min, writes tools/gpx/.cache/adana-osm.json.gz.
tools/regions/.venv/Scripts/python tools/gpx/extract_osm.py --pbf tools/regions/.cache/turkey-261115.osm.pbf

# 2) Generate all routes (standard library only). OSRM responses are cached in tools/gpx/.cache/http/,
#    so only new or changed routes call the demo server (>= 1.5 s between requests).
python tools/gpx/generate.py
python tools/gpx/generate.py --only residential parallel-roads
python tools/gpx/generate.py --offline      # fail instead of calling OSRM

# 3) Tests (pytest pinned in tools/gpx/requirements.txt, the only dependency of the generator and tests)
python -m pip install -r tools/gpx/requirements.txt
python -m pytest tools/gpx/tests
```

`tools/gpx/.cache/` (OSM extract cache, OSRM responses, `request-log.json` with every request made) is git-ignored. A new OSM extract can change node ids and the expected files; regenerate both the region package and these routes from the same extract.

## Replaying on the emulator

```bash
adb devices                                                     # find the serial, e.g. emulator-5554
python tools/gpx/replay.py test-data/gpx/main-roads.gpx -s emulator-5554                 # real time, 1 Hz
python tools/gpx/replay.py test-data/gpx/main-roads.noisy.gpx -s emulator-5554 --speed 4  # 4x faster
python tools/gpx/replay.py test-data/gpx/intercity.gpx --method fix --start 600 --limit 120
```

- Each point is sent at its own timestamp divided by `--speed`; dropouts in noisy files are replayed as gaps. `--start` / `--limit` select a slice, `--dry-run` prints the commands.
- `--method fix` (default) sends `adb emu geo fix <lon> <lat> 30 10 <knots>`: position, altitude 30 m, 10 satellites and **speed**. Verified on the `Pixel_8` emulator (2026-11-16, Google Maps holding a GPS request): `dumpsys location` showed `gps 37.041755,35.313293 vel=15.520776` and 15 s later `gps 37.040240,35.314632 vel=14.51761`, i.e. position advances and `vel` is the track speed in m/s. Course is **not** carried (`bear=0.0`): the app must derive bearing from consecutive points. The emulator GPS HAL reports at 1 Hz, so with `--speed N > 1` only the latest fix of each second reaches Android (positions jump N points per fix).
- `--method nmea` sends `$GPGGA` + `$GPRMC` (`adb emu geo nmea`). On the same emulator the console answers `OK` but the location does not change, even for textbook sentences; kept only for other emulator builds.
- With `--speed N` the wall-clock time between fixes shrinks N times but the speed field keeps the real value, so speed derived from positions/time is N times higher than the reported speed. Drive-detection timeouts (3 / 5 min) also shrink in track time: use `--speed 1` for `traffic-stop` / `traffic-stop-long`.
- A location only shows up in `adb shell dumpsys location` (`gps provider: last location=...`) while some app is requesting GPS updates.
